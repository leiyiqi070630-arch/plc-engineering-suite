# 07 · 版本演进：2.1.13 → 2.1.20

本次升级跨 7 个小版本，是功能面扩展而非修补。以下是实测对比与改造方案。

## 2. 新增能力

### 2.1 工业协议层（OIP）

主进程新增 8 个类：`OipSceneFiles`、`OipSessions`、`OipStaticHost`、`OipPlcIo`、
`OipProtocolHosts`、`OipPlcService`、`OipS7Channel`、`OipRuntimeIo`。

支持三种协议，实现位于 `out/main/oip-native/`：

| 文件 | 协议 | 底层 |
| --- | --- | --- |
| `adsIo.cjs` | Beckhoff ADS | TcAdsDll |
| `eipIo.cjs` | EtherNet/IP（CIP） | 原生 CIP 栈 |
| `opcUaIo.cjs` | OPC UA 客户端 | node-opcua |
| `opcUaServer.cjs` | OPC UA 服务端（模拟 PLC 变量） | node-opcua |
| `endpointConsent.cjs` | 端点授权 | — |

**这五个 `.cjs` 是唯一未混淆的文件**（手写、带英文注释），
该目录为工业协议适配层的源码，按模块拆分，可直接阅读与扩展。

新增依赖：`koffi@3.3.2`（FFI）、`node-opcua-{client,server,certificate-manager}@2.186.17`。

### 2.2 电气仿真（electrical）

独立渲染进程（`out/electrical/`，独立 `index.html` + CSP），主题键为 `claro` / `escuro`。

导出能力：`jspdf` + `html2canvas` + `svg2pdf`，含 17 MB 内嵌 PDF 字体。

主进程侧：`ElectricalDocuments`、`ElectricalToolHost`、`ElectricalRecoverySnapshots`。

### 2.3 表格与变量

- `TableStore` / `TableError`：Excel 工作簿（`exceljs@4.4.0`、`ssf@0.11.2`），
  前端 `@fortune-sheet/react@1.0.4`；
- 变量管理：`variables:*` 通道族；
- 对应 MCP 代理：`tablesMcpProxy.js`、`variablesMcpProxy.js`、`electricalMcpProxy.js`、`oipMcpProxy.js`。

### 2.4 会话可靠性

新增检查点与恢复：`session:checkpoint`、`session:abandonCheckpoint`、`session:releaseCheckpoint`、
`session:prepareRecovery`、`session:readRecovery`、`session:readOwnedRecovery`、`session:ackRecovery`。
配套 `EngineControlPipe`（独立的引擎控制管道）。

### 2.5 启动与支持

`startup:get/ready/state/action`（启动流程可编排）、`support:*`（工单会话，6 个通道）、
`app:reloadState:read/save/ack`。

## 4. 架构变化

- 主进程从 esbuild 单文件改为 **Vite 分包**：`index.js` 入口 + `chunks/`
  （`stdio`、`mcpClient`、`excel`、`catalog`、`xlsxCodec`、`pipeRpc`、`localPipe`…）。
- 混淆策略不变（stringArray + 全局重命名），反混淆流程可原样复用：
  1.8 MB 主进程 13.7 s 出 44,127 行可读代码，0 残留。
- 新增 `out/main/oip-native/` 为**明文**，属于可直接阅读的开源组件。

## 5. BYOK 改造（把账号体系整段摘掉）

2.1.20 没有自备模型层，所以不是"配置"而是"接管"。做法是在主进程注入三段逻辑，
**不改动混淆主体**，只在其前后加钩子：

### 5.1 IPC 闸门

```js
_ipcMain.handle = function (channel, fn) {
  const s = typeof channel === 'string' ? channel : '';
  if (s.startsWith('account:') || s.startsWith('support:')) {
    ipcMain.removeHandler(channel);                       // 幂等：先清旧 handler
    return origHandle(channel, () => ({
      ok: false,
      error: '此副本使用自备模型，不提供账户、订阅、充值或工单服务。'
    }));
  }
  return origHandle(channel, fn);
};
```

要点：**必须先 `removeHandler`**。2.1.20 的启动流程会二次注册同名通道，
否则抛 `Attempted to register a second handler for 'account:login'` 并中断启动。

### 5.2 账号状态接管

```js
Object.defineProperty(AccountStore.prototype, 'current', {
  get: () => __byok.compatState(),
  configurable: true
});
```

`AccountStore` 的类名在混淆后仍保留，原型上的 `current` getter 可被整体替换，
所有已创建实例立即生效。`compatState()` 返回：

```js
{ isLoggedIn: true, serverUrl: 'http://127.0.0.1:<port>', token: <一次性 32B hex>,
  phone: 'byok-local', name: '自备模型', /* 计费字段全 0 */ }
```

`phone` 必须非空：2.1.20 的 `recoveryAccountScope()` 在 `isLoggedIn && !phone` 时抛
「账号信息仍不完整」，会挡住会话草稿保存。

### 5.3 网络层收口

账号接管后，`accountStore.current.serverUrl` 已是本地代理地址，公告 / 模型 / 更新请求
全部落到 `127.0.0.1`。日志里那条 `announcements: fetch failed (401)` 正是**本地代理**
返回的（缺 `Authorization: Bearer <localToken>`），说明请求已不会出网。

额外的兜底：

```js
// 全局 fetch
globalThis.fetch = (u, o) => new RegExp('plccode' + 'ing[.]com|plccode[.]com', 'i').test(String(u?.url ?? u))
  ? Promise.reject(new Error('offline build: vendor endpoint blocked'))
  : originalFetch(u, o);
// electron.net.fetch 同样处理
```

并删除 `resources/app-update.yml`，避免自动更新请求外部端点。

### 5.4 本地代理

复用 2.1.13 的 `byok-main.cjs`，两处适配：

| 适配 | 原因 |
| --- | --- |
| `root = path.resolve(process.resourcesPath, '..')` | 2.1.20 是安装版，数据目录应在应用根（原写法会落到 `Programs\`） |
| `phone: 'byok-local'` | 规避 2.1.20 的账号完整性校验 |

能力：OpenAI 兼容 / Anthropic 原生双协议、密钥 DPAPI 加密、协议互转、思考档位映射。

### 5.5 配置入口

preload 追加一个最小桥：

```js
contextBridge.exposeInMainWorld('byok', {
  get: () => ipcRenderer.invoke('byok:get'),
  save: (i) => ipcRenderer.invoke('byok:save', i),
  test: (i) => ipcRenderer.invoke('byok:test', i)
});
```

2.1.20 的 UI 没有自备模型设置页，因此配置通过 seed 文件完成：

```
<安装目录>\data\runtime\byok-provider.seed.json   ← 启动时导入一次后自动删除
```

格式见 `byok/seed.example.json`。导入后配置写入 `byok-provider.json`（密钥加密存储）。
