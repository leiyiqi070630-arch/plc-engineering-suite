# 04 · 引擎与工具链协议

主进程不实现任何 PLC 逻辑，它只是**编排器**：把 UI 的意图转成子进程 stdin 的 JSON 行，再把子进程的 JSON 行
转成 UI 事件。所有真正的能力在这几个外部组件里。

## 1. plceng-engine.exe（Rust agent）

**调用形式**

```
plceng-engine.exe [--model M] [--permission-mode P] [--reasoning-effort E] bridge
```

- `bridge` 子命令 = 长驻 JSON-Lines 会话模式（stdio 双向）。
- `--permission-mode` 决定工具写盘权限，代码里出现过 `workspace-write` 这一档。
- `--reasoning-effort` 取值来自设置的 `reasoningEffort`（`auto` 时不下发）。

**消息（一行一条 JSON）**

| 方向 | 形态 |
| --- | --- |
| 下行 | 渲染进程的 turn 对象：`{prompt, input_kind, presentation?, id, …}` |
| 下行 | 控制命令：`{command:"cancel", scope:"all"}`、`{command:"capabilities"}`、`{command:"shutdown"}` |
| 上行 | `{type:"ready", session_id}` / `{type:"turn", …}` / `{type:"event", event:"question"|"question_cleared", …}` / `{type:"shutdown"}` |

**生命周期约束**

- spawn 后 60s 未收到 `ready` → 判 `ENGINE_READY_TIMEOUT` 并 kill（`startupTimer`）。
- `stdout` 逐行 `JSON.parse`，解析失败进 `malformed` 分支（不崩，只上报）。
- `close` 事件里若「非主动 dispose 且未收到 shutdown ack」→ 判定 crash，交给 `createEngineFailureRecorder()`
  写诊断（含脱敏后的 env 快照：凡 `/(KEY|TOKEN|PASSWORD|SECRET|AUTHORIZATION)$/i` 的变量都会被替换）。
- 优雅退出：`cancel(all)` → `shutdown` → 等 2s → kill。

**能力注入（env）**：见 `docs/01` §3。其中 `PLC_CODE_THINKING_TIERS/KINDS/FIELDS`、`PLC_CODE_VISION_MODELS`、
`PLC_CODE_AVAILABLE_MODELS` 是"把模型能力告诉引擎"的通道 —— 这也是为什么 本实现能适配任意 OpenAI 兼容服务：
能力清单是运行时算出来的字符串，不是编译期常量。

## 2. execute_tool.exe（工具执行器）

主进程用统一外壳 `runTiaTool()` 调用：

```js
runTiaTool(exePath, cwd, command, ?, timeoutMs)
// → spawn(exe, [command], {stdio:pipe, windowsHide:true})
// → 超时 kill 并抛 TIA_DIAGNOSTIC_TIMEOUT
// → exit !== 0 时把 stderr+stdout 丢给 tiaToolFailure()
```

`tiaToolFailure()` 是一个**容错 JSON 提取器**：从混杂日志里扫第一个能 `JSON.parse` 的平衡 `{}` 块（自己做了
字符串/转义处理），读 `error.code` / `error.code`；捞不到就用正则 `\bTIA_[A-Z0-9_]+\b` 兜底，
最终退化为 `TIA_DIAGNOSTIC_FAILED`。这套逻辑存在的原因是：.NET 桥会把 Siemens 的异常信息直接打到 stderr，
格式不稳定。

已知的错误码族（从代码与文案归纳）：`TIA_DIAGNOSTIC_FAILED`、`TIA_DIAGNOSTIC_TIMEOUT`、
`TIA_DIAGNOSTIC_PIPE_FAILED`，以及桥自己抛的 `TIA_*`。UI 侧把它们映射成「通道未就绪 / 版本锁冲突 /
需要 Openness 用户组 / 需要信任连接」四类处置动作（`tiaAdminFlagDoctor`、`tiaAdminFlagRepair`、
`tiaJoinOpennessGroup`、`tiaTrustBridge`、`tiaVersionLockRead/Write`）。

## 3. TiaOpennessBridge.exe（.NET Framework 4.8）

- 依赖 Siemens 官方 `Siemens.Engineering*.dll`（**不随包分发**，`versions.json` 里 `doNotBundle` 明确禁止捆绑）。
- `attachMode: "attach-ui-first"`：优先附加用户已打开的 TIA 实例。
- 各版本路由与可信度分级在 `resources/routes/versions.json`：

| 版本 | apiLayout | SIMATIC SD |
| --- | --- | --- |
| V15–V17 | classic-single-dll | 不可用（SD 需 V20+） |
| V18 | classic-single-dll | 不可用 |
| V19 | classic-single-dll | 不可用 |
| V20 | classic-single-dll-or-package | `source-verified`，LAD/DB/UDT（SCL 需 V20 Update 4） |
| V21 | split-net48-candidate | `source-verified`，LAD/FBD/SCL/DB/UDT/混排，**无 STL** |

V20/V21 的「方言陷阱」值得单独记：`.s7dcl` 头必须匹配目标门户（V20 用 `S7_Language`，V21 用
`S7_PreferredLanguage`+`S7_Version`）。方言不匹配时 Siemens 报的是
「Block Language is not defined | .s7res has no en-US entries」—— **这个报错是误导性的**，
真因在方言而非 `.s7res`（实测：V20 的空 `.s7res` 块在 V20 上能正常导入）。

## 4. MCP 客户端（`chunks/mcpClient-*.js`）

内嵌 `@modelcontextprotocol/sdk` 的打包产物 + 一个 JSON-Schema 校验器（ajv 风格代码生成）。

- 传输层：`StdioClientTransport` / `SSEClientTransport` / `StreamableHTTP` / `ws`，四种都由代码路径覆盖。
- 能力：`ListTools`、`ListResources`、`callTool`。
- 用途：① 设置页的「MCP 服务器测试」（`workbench:mcp-test` / `workbench:mcp-cancel`）；
  ② 把桌面侧 MCP 配置序列化进 `PLC_CODE_DESKTOP_MCP_CONFIG` 交给引擎，让 agent 能调用外部工具。

## 5. computer-use（Windows UIA）

`resources/computer-use/mcp/server.mjs` 是一个**独立可读**的 MCP 服务器（v0.1.3，协议 `2024-11-05`）：

- 后端：`scripts/windows-uia.ps1`（PowerShell + UIAutomation），可用 `WINDOWS_CU_POWERSHELL` 覆盖解释器。
- 资源：把 `docs/wiki/*.md` 以 `windows-computer-use://wiki/*` 暴露给模型（架构、安全、工具清单）。
- 主进程侧：`computerUseMcpConfig()` 只在 `win32` 注入，`ComputerUseActivity` / `ComputerUseIndicator`
  两个类负责活动指示与「计算机正在被操作」的 UI 状态。

## 6. Python 侧

`resources/engine/python/` 是内嵌的 CPython 3.12（`python312.zip` + 若干 `.pyd`），
`applyPortablePythonEnv(env, prefix)` 把 `PYTHONHOME`/`PYTHONPATH` 指向它，使引擎可以跑：

- `engine/lint_plc/`：PLC 代码 linter（三菱 FX2/FX3、S7-200 的 AWL/ST 规则、八进制地址校验、
  双线圈/死锁检测 `fx3u_coil_deadlock` 等），规则以 `rules/**/profile.json` + `syntax_rules.json` 描述。
- `engine/siemens_rag/`：Siemens 文档检索（`build_rag_context` / `search_rag` / `retrieval_contract`），
  配合 `createRagLease()` 的租约机制使用。
- `inoproshop/codesys-bridge/`：CODESYS/InoProShop 的 MCP 桥（`mcp_server.pyc`、`lad_generator.py`、
  `contact_lad_compiler.py`、`vendor_contract_gate.pyc` 等）。

## 7. 想替换引擎的最小契约

1. 实现 `bridge` 子命令：读 stdin 的 JSON 行，先吐 `{"type":"ready","session_id":"…"}`。
2. turn 输入 → 你的 agent 循环 → 期间可发 `{"type":"event","event":"question",…}` 向 UI 提问。
3. 每轮结束发 `{"type":"turn", …}`；收到 `{"command":"shutdown"}` 回 `{"type":"shutdown"}` 后退出。
4. 从 env 读模型配置（`PLC_CODE_*` / `OPENAI_*`），不要自己读用户的密钥文件。

满足这 4 条，整个 UI、会话存储、工作区、更新机制都能复用。
