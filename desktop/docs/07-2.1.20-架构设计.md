# 07 · 2.1.20 架构设计

2.1.20 在 2.1.13 的核心工具链之上，新增了四块能力：**工业协议层**、**电气工作台**、**表格**、
**会话检查点**。这一版的重点从"生成正确的块"扩展到"让程序在现场可观测、可验证"。

## 1. 包体与分层

| 项 | 2.1.13 | 2.1.20 | 说明 |
| --- | --- | --- | --- |
| 应用载荷 | 130.6 MB / 13,439 文件 | 224.5 MB / 22,558 文件 | 新增能力带来 |
| 主进程 | 574 KB 单文件 | 6.8 MB / 26 文件 | 改 Vite 分包 |
| 渲染进程 | 37 MB | 42.8 MB | 表格与图表组件 |
| 电气工作台 | — | 21 MB 独立渲染进程 | 独立 CSP 与生命周期 |

主进程改分包是为了让**协议层与工具层可以独立加载**：不打开电气页就不加载电气宿主，
不连 PLC 就不加载协议栈。单文件包做不到这一点。

## 2. 工业协议层

现场调试绕不开"程序在不在跑、值对不对"，而各家 PLC 的在线通道完全不同。这一层把三种协议
收敛成同一套读写语义。

| 实现 | 协议 | 用途 |
| --- | --- | --- |
| `adsIo.cjs` | Beckhoff ADS | 变量读写、状态读取 |
| `eipIo.cjs` | EtherNet/IP（CIP） | Logix 系列 tag 读写 |
| `opcUaIo.cjs` | OPC UA 客户端 | 通用客户端 |
| `opcUaServer.cjs` | OPC UA 服务端 | 把仿真变量暴露给上位机 |
| `endpointConsent.cjs` | 端点授权 | 未授权端点一律拒绝连接 |

主进程侧配套 8 个宿主类（场景文件、会话、静态资源、PLC IO、协议主机、S7 通道、运行时 IO）。

### 2.1 关键设计：不阻塞主进程

所有读写都用**非阻塞 + 轮询**：

```
create/read/write 一律 timeout=0（立即返回 PENDING）
→ 每 2 ms 轮询状态
→ 单请求上限 1000 ms（对 20 ms 扫描周期足够，又能在 PLC 掉线时及时放弃）
```

同步调用会让整个应用在"PLC 掉线"时冻结一整屏，这是不可接受的。

### 2.2 关键设计：端点需要显式授权

`endpointConsent.cjs` 记录用户放行的网络端点。主进程在连接前询问，未放行直接拒绝。
这条约束让"AI 去读某个地址"不能绕过人的决定。

### 2.3 原生依赖的处理

FFI 走 `koffi`，协议库是平台原生文件，构建时按平台取：

```
vendor/libplctag/{plctag.dll | libplctag.dylib | libplctag.so}
```

打包后原生文件必须在 `app.asar.unpacked` 下（原生库无法从 asar 内加载）。
构建缺这个文件时，连接会给出明确说明而不是崩溃。

## 3. 电气工作台

独立渲染进程（`out/electrical/`，自带 `index.html` 与 CSP），与主界面的生命周期解耦。

| 能力 | 实现 |
| --- | --- |
| 元件绘制 / 连线 | 独立画布层 |
| 导出 PDF | `jspdf` + `svg2pdf`（矢量，不损失线条） |
| 导出 PNG | `html2canvas` |
| 字体 | 内嵌 PDF 字体，保证导出不依赖系统字体 |
| 恢复 | `ElectricalRecoverySnapshots`（主进程侧快照） |

主进程侧对应 `ElectricalDocuments`、`ElectricalToolHost`、`ElectricalRecoverySnapshots`，
以及 `electrical:*` 通道族（open / attach / close / command / context / changed / requested / ai-context）。

## 4. 表格

`TableStore` 负责工作簿的读写与并发控制，格式层用 `exceljs` + `ssf`，前端用 `@fortune-sheet/react`。

设计要点：

- **只读优先**：解析与导出不改变原文件；
- **并发保护**：同一工作簿的写操作串行，避免半写状态；
- **错误结构化**：`TableError` 携带单元格坐标，便于定位。

## 5. 会话检查点

长任务的痛点是"跑到一半断了"。2.1.20 引入检查点与恢复：

```
session:checkpoint / abandonCheckpoint / releaseCheckpoint / checkpointReleased
session:prepareRecovery / readRecovery / readOwnedRecovery / ackRecovery
```

配套 `EngineControlPipe`：一条独立于业务数据的控制通道，用于让引擎在恢复时
"停下、对齐、再继续"，而不是靠超时判断。

## 6. 变量管理

`variables:*` 通道族提供跨工程的信号表：读写当前值、订阅变化（`signals-changed`）、
按工程隔离（`requested`）。

## 8. 未变的约束

这一版没有放松任何验收要求：

- 编译通过仍不等于运行正确；
- 写操作仍走影子副本 + 显式提升；
- 不支持的能力仍明确拒绝；
- 工具回执仍区分四档证据。

新增能力只是扩大了"能观测到什么"，没有降低"什么算证明"的门槛。
