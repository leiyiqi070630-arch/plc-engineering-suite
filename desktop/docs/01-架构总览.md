## 2. 启动顺序（`main/index.js` 的 `app.whenReady` 路径）

1. `locateEngine()`：按 `PLC_CODE_ENGINE_PATH` → 仓库探测（向上 12 层找 `rust/Cargo.toml`）→ 打包目录三级回退，定位
   `plccode-engine.exe` 与 `TiaOpennessBridge.exe`。
2. `installProcessCrashGuard()`：注册 renderer 崩溃/无响应处理，写崩溃报告到 `runtimeHome()/crash-*`。
3. 建主窗口，加载 `out/renderer/index.html`（`file:` + `app.asar` 路径），注 入 preload。
4. `registerWorkbenchIpc` / `registerViewerIpc` / 会话、工作区、画布、TIA、更新、公告各注册函数依次挂载 IPC。
5. `gateway.initialize()`：若存在 `model-provider.seed.json` 则一次性导入配置并删除种子；随后 `gateway.register()` 挂
   `model:get|test|save` 三个通道，并把 `account:*` 一族通道替换成固定失败响应。
6. 若 `accountStore.current.isLoggedIn`（恒为 true，见 `localState()`），异步 `meAsync` / `listModelsAsync` 刷新。
7. 更新与公告：默认离线构建不联网；设置 `PLC_CODE_ANNOUNCEMENT_SOURCE` 或配置更新源后才请求远端。
8. 用户发第一句话时 `ensureBridge()` 才 spawn 引擎子进程（懒启动，每会话一个）。

## 3. 引擎驱动（EngineBridge）

`EngineBridge` 是一个 `EventEmitter`，负责一个会话对应的一棵引擎子进程：

- **spawn**：`plccode-engine.exe [--model M] [--permission-mode P] [--reasoning-effort E] bridge`，
  `stdio: pipe`，`windowsHide: true`，60s 内必须收到 `{"type":"ready"}`，否则判 `ENGINE_READY_TIMEOUT`。
- **环境变量注入**（关键契约，删掉任一即降级）：
  `PLC_CODE_RUNTIME_HOME`、`PLC_CODE_SESSION_WORKSPACE_ROOT`、`PLC_CODE_BRIDGE_RESUME_SESSION`、
  `PLC_CODE_DESKTOP_MCP_CONFIG`、`PLC_CODE_TIA_OPENNESS_BRIDGE_EXE`、`PLC_CODE_AGENT_MODEL`、
  `PLC_CODE_VISION_MODELS`、`PLC_CODE_AVAILABLE_MODELS`、`PLC_CODE_THINKING_TIERS/KINDS/FIELDS`、
  `PLC_CODE_HTTP_PROXY`、`OPENAI_API_KEY` + `OPENAI_BASE_URL`（网关走这条）、
  `CLAUDE_CONFIG_DIR`、`CLAUDE_CODE_AUTO_COMPACT_INPUT_TOKENS`，
  另有 `PLC_CODE_ENABLE_PLC_PROMPT_EXTENSION`、`PLC_CODE_SKIP_PROJECT_INSTRUCTIONS`。
- **协议**：一行一条 JSON。下行 = 渲染进程传来的 turn 对象（`prompt` / `input_kind` / `presentation` 等）或
  `{command:"cancel"|"capabilities"|"shutdown"}`；上行 = `{"type":"ready"|"turn"|"event"|"shutdown", ...}`，
  其中 `event` 再分 `question` / `question_cleared` 等状态。
- **写队列**：`send()` 入队 + `pump()` 串行写，避免背压；`stopGracefully()` 先发 `cancel` 再发 `shutdown`，
  2s 未退则 kill。
- **RAG 租约**：`createRagLease()` 在 runtimeHome 生成一次性 guard 文件路径，配合 `PLC_CODE_RAG_SERVER` +
  `PLC_CODE_RAG_ACCOUNT_TOKEN` 使用；进程关闭时 `invalidateRagAccess()` 撤销。

## 3.1 MCP 代理（`mcpProxy.js`）

主进程用 `workbenchStore.writeMcpRuntimeConfig(process.execPath, mcpProxy.js, ...)` 生成一份运行时 MCP 配置，
路径通过 `PLC_CODE_DESKTOP_MCP_CONFIG` 交给引擎。引擎按配置以 `process.execPath mcpProxy.js` 拉起代理进程，
代理再转发到真正的 MCP 服务器（如 `windows-computer-use`）。这样引擎不需要了解每个 MCP 服务器的启动细节，
也把「哪些 MCP 被允许」收敛在主进程一处。`mcpProxy.js` 573 行，已反混淆。

## 4. 工作区与 staging

三层目录语义（全部在 `runtimeHome()` 之下）：

| 层 | 用途 |
| --- | --- |
| `drafts/` | 未绑定真实工程时的草稿工作区，可整体迁移 |
| `staging/` | 绑定真实工程后的**影子副本**：AI 只写这里 |
| 真实工程目录 | 只有用户在画布上确认后，`promoteOneFile()` 才把 staging 里的文件覆盖写入 |

关键函数链：`bindWorkspace` → `seedStaging`（按真实文件播种）→ `WriteCanvasFiles`（写 staging）→
`CheckRealFileDrift`（真实文件是否被外部改动）→ `promoteOneFile`（提升，带编码/换行归一）→
`resetStagingFromReal`（回滚）。EXCEL/CSV 走 `parseCsv`/`serializeCsv`，MicroWIN 走 `decodeMicroWinBuffer`。

这套设计就是原产品「AI 不直接改你的 PLC 工程」的实现方式，改动它等于改变安全边界，慎重。

## 5. TIA 工具链

`runTiaTool(exe, cwd, command, ...)` 是统一外壳：spawn `execute_tool.exe <command>`，超时 kill，从 stderr/stdout
里**扫描第一个可解析 JSON 对象**并读 `error.code` / `error.message`（`tiaToolFailure()` 里那个手写括号配平扫描器
就是为了从混杂日志里捞出 JSON），提取失败码形如 `TIA_*`。

上层诊断函数：`parseTiaStatus`、`parseEnvironmentHealth`、`statusText`、`tierText`、`probeFailureReport`，
把结果组织成「通道/权限/版本锁/信任邀请」四类 UI 状态。`versions.json` 里明确写了各 TIA 版本的能力真值
（planned / source-verified / local-detected / local-verified），这是原产品的可信度分级，别当成营销文案。

| 品牌 | 桥 | 形态 |

| 西门子 TIA Portal | `TiaOpennessBridge.exe` + `Sharp7.dll` | .NET Framework 4.8 + Openness |
| 三菱 GX Works2/3 | `GxWorks2Bridge.exe` | 原生桥 + CSV/ST 交换 |

| 威纶通 EasyBuilder | `resources/weinview/*.ps1` + `*.cs` | PowerShell 驱动 + C# 反射控件封装 |
| 仿真 | `PlcSimClassicSidecar.exe`、`PlcSimStandardSidecarV18–V21` | 各 TIA 版本 x86/x64 sidecar |

桥的路由真值表在 `resources/routes/route-metadata.json`（familyToken 匹配规则 + 路由清单 +
默认模型 + lint profile），由 Rust 引擎的 `route_metadata::canonical_family` 与桌面端共用同一份。
