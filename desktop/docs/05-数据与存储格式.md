# 05 · 数据与存储格式

## 1. 运行时根目录

```js
buildRuntimeHome(identity, base, override) =
  override (PLC_CODE_RUNTIME_HOME) 有值 → path.resolve(override)
  否则 → path.join(base, DATA_NAMES[identity.channel], "runtime")
```

`base` 取 `LOCALAPPDATA`（回退 `app.getPath('userData')`），`DATA_NAMES` 按发布通道分目录：

| channel | 目录名 |
| --- | --- |
| `stable` | `PLC Code Electron` |
| `demo` / `demo2` / `demo5` | `PLC Code DEMO` / `DEMO2` / `DEMO5` |
| `development` | `PLC Code Development` |
| 未知 | `PLC Code Unclassified` |

即默认 **`%LOCALAPPDATA%\PLC Code Electron\runtime`**。

> 注意 网关集成还会把 `app.setPath('userData', <resourcesPath>/../../data/chromium)`，
> 所以 Chromium 的缓存/存储落在**安装目录旁的 `data/chromium`**，而业务数据仍在 `runtime/`。
> 两者分离是刻意的：便携版删安装目录即清干净，卸载不残留业务数据。

## 2. 目录布局

```
runtime/
├─ sessions/
│  └─ <sessionId>/
│     └─ session.jsonl         # 会话事件流（追加写）
├─ drafts/
│  └─ <draftId>/               # 未绑定真实工程的草稿工作区
├─ staging/                    # 绑定真实工程后的影子副本
├─ settings.json               # 设置（含 reasoningEffort）
├─ model-provider.json          # 自备模型配置（apiKey 加密存 keyProtected）
├─ model-metadata.json    # 模型能力探测结果缓存
├─ account.json                # 账户状态（不写盘）
├─ crash/                      # 崩溃报告
└─ model-provider.seed.json     # 一次性种子（导入后即删）
```

`drafts/` 有 **200 MB 预算**（`DRAFTS_BUDGET_BYTES = 209715200`），`purgeOldDraftsIfOverBudget()` 按时间清理最旧的草稿。

## 3. 会话（session.jsonl）

- 一行一个事件，`reconstructHistory()` 负责把它重构成 UI 的卡片流。
- 分片函数：`appendUserBlock` / `appendAssistantBlocks` / `appendToolResultBlocks`，
  文本抽取 `extractContentText`，媒体用 `readMediaPayload` / `imageBlockToAttachment`（图片转附件）。
- 特殊处理：
  - `stripLeadingSystemReminder` / `stripInjectedContext`：把注入的 system-reminder、`<context>` 块从展示里剥掉；
  - `blocksLookContinued`：判断被截断的流式块是否需要拼接；
  - `markInterruptedTailCards`：进程中断时把尾部卡片标记为「已中断」；
  - `collectAgentIdsFromHistory` / `collectWorkflowIdsFromHistory`：收集子 agent / 工作流 id 用于树状视图。
- 元数据操作：`rewriteSessionMetaLine`（原位改写元数据行）、`uniqueForkId` + `forkSession`（派生新会话）、
  `deleteSession`、`pin`、`rename`、`generateTitle`（`requestSessionTitle` / `requestSessionTitleBatch`）。
  标题生成有 `deriveFallbackSessionTitle()` 兜底，`sanitizeGeneratedTitle()` 清洗，批量时 `parseBatchTitles()`。
- 安全：`resolveAllowedSessionFile()` 把路径限制在 `<runtime>/sessions` 之内（防路径穿越读任意文件）。

## 4. 工作区与 staging 推进

文件分类（决定哪些会进 staging / 哪些只是产物）：

```js
SOURCE_EXTENSIONS   = { .st, .scl, .awl, .stl, .csv, .xml }
ARTIFACT_EXTENSIONS = { .md, .markdown, .txt, .rst, .log, .py, .ps1, .sh, .bat, .cmd,
                        .json, .yaml, .yml, .ini, .toml, .s7dcl, .s7res }
```

推进链路：

```
真实工程 ──seedStaging()──► staging（影子副本，AI 只能写这里）
   ▲                              │
   │                              │ WriteCanvasFiles
   │                              ▼
   └──promoteOneFile()──── 用户确认后逐个提升
        ▲
        └── CheckRealFileDrift() 先比对真实文件是否被外部工具改过（防覆盖）
```

- `countUnpromoted()`：统计 staging 里尚未提升的改动，用于 UI 提示。
- `resetStagingFromReal()`：把 staging 整体回滚到真实工程状态。
- `writeStagingFile()` 会做换行归一：`normalizeToLf` / `normalizeToCrlf`（按目标文件原换行风格），
  编码用 `encodeWorkspaceFile()`；读取时 `decodeCsvBuffer`（BOM/GBK 探测）、`decodeMicroWinBuffer`
  （S7-200 MicroWIN 的 GBK 文本）。
- `readProjectConfig()` / `writeProjectConfig()`：识别工程配置文件（`looksLikeDevRepo` / `hasProjectConfig`），
  没找到时 `seedMainFile()` 生成主文件骨架。

## 5. 画布文件

画布不是自由画板，它绑定真实文件：

- `ReadCanvasFile` / `ReadCanvasImage`：读工程内文件（含图片），`assertCanvasTextPath` 限制扩展名。
- `ReadUnboundCanvasFile`：未绑定工作区时读草稿。
- `WriteCanvasFiles`：写 staging（不是真实工程）。
- `WriteRealFile`：**直接写真实文件**，参数里带预期 hash/漂移检查，属于显式用户动作。
- `ReadStagingSnapshot` / `DiscardWorkspace`：快照与丢弃。

## 6. 设置与其它

`settings.json` 目前确认被读的字段：`reasoningEffort`（`auto|low|medium|high|…`）。
`settingsHotSwap` 允许运行中改设置而不重启（切换 effort / 代理等）。

`account.json`：由 `localState()` 伪造在内存里，**不写盘**（代码注释明确写了 never saved to account.json）。

崩溃：`writeCrashReport()` 落在 `crash/`，`planRendererRecovery()` 决定渲染进程崩溃后是重载还是提示。
