> Scope: facts for TIA Portal V18 with S7-300. Evidence labels preserve the source strength; a fact verified on another release is not promoted to verified here. Source basis: repository generator/runtime contracts, the shared environment reference, and the real-machine evidence cited here.

## Authoring and validation

- [delivery] Generate the requested block set directly and land related objects in one dependency-ordered batch. The generator validates its own plan; specification, evidence, and export tools are diagnostics for a concrete failed shape.
- [rule] For every non-Bool FB-call formal parameter, provide `datatype` explicitly. An omitted type can render as Bool and fail only at import/compile.
- [rule] Power-flow pins and data pins are different. TON.IN and counter CU/CD/R/LD consume power flow; PT/PV/value operands use data accesses. Do not wire an Access directly to a power-flow pin.
- [V18-grounded XML] ADD/MUL are variadic and require `Card`; SUB/DIV are binary; MOVE uses `out1`; comparators use `pre`; CALCULATE is the `Calc` part with an Equation.
- [instruction facts] Ones' complement is `INVERT`, not `INV`. SR is reset-dominant; RS is set-dominant. CTD output is `Q`; QU/QD belong to CTUD. SCL inputs use `:=`, outputs use `=>`.
- [block rule] FC cannot contain a stateful `VAR` section; use formal parameters and `VAR_TEMP`, or use an FB for retained state.
- [tag rule] Omit `table_name` to use TIA's localized default tag table. Never assume the English name `Default tag table`.
- [persistence] Mutation tools default to an unsaved in-memory change. Save once at meaningful milestones after device creation, completed block import, or successful compile.
- [retentivity] LAD XML generation does not emit member remanence and rejects a `retain` plan field. Use a supported SD `var_retain` route where available, SCL/DB `VAR RETAIN`, or configure retain on the real object; never silently ship a non-retentive result.
- [learning] Experiments stay unsaved, use temporary names, and must be deleted and confirmed. Requested project work is preserved at explicit milestones.

## CPU-family rules

- [real-machine verified family route] Pass `target_family` as the exact classic family and always provide `block_number`; classic blocks have no AutoNumber.
- [warning] The LAD generator can normalize declared TON/CTU members to optimized `TON_TIME`/`CTU_INT`, but those spellings are verified only on S7-1200/1500. Classic CPUs use SFB timer/counter instances. Treat a classic import error about unsupported data type as this mismatch, not as a wire error.
- [classic OB] Classic CPUs use standard access and at least 20 bytes of local start information. The LAD generator reserves it automatically; text source declares the corresponding start data.
- [runtime] For ISO-on-TCP reads of a real classic CPU, rack/slot commonly resolves to 0/2. Probe identity first and do not rotate rack/slot values blindly.
- [hardware] Address decisions must use identifiers, positions, and catalog data rather than translated rack/module names. Process I/O must be backed by configured modules.

## Simulation and behavioral proof

- [simulation] When simulation is requested, `tia_plcsim_plan` returns the compatible route and package set in one call; environment diagnostics are used when that route reports an environment problem.
- [behavior route] Requested behavioral simulation runs as one continuous compile -> download -> RUN -> stimulus -> observed readback sequence.
- [timed behavior] `tia_plcsim_assert_behavior` combines pulses, delays, latches, and timed assertions in one call when those checks are part of the request.
- [runtime ownership] The selected simulator tool family owns its runtime lifecycle. Trust/UAC/modal cards pause and resume that same operation.
- [network] Standard PLCSIM uses its Softbus route; PLCSIM Advanced exposes TCP/IP when started in TCP/IP network mode.
- [route-defined] Use installed 32-bit S7ProSim V5.4/S7ONLINE through the standard tool surface; there is no IP-suite step.
- [evidence status] The detailed download and behavior proof is real-machine verified on V18. For V18, keep that provenance explicit unless this exact combination is observed.
- [classic contract] RUN must return `executionProven=true`. Continuous scan does not survive sidecar disconnect, so write with `scan_cycles` or call scan before reading.
- [areas] PI/M/DB are writable; Q is read-only; input image cannot be read. Confirm PI stimuli through Q/M behavior. Fault injection is unavailable.

## Online values and configuration

- TIA Openness itself cannot read current values. Use the separate S7 runtime channel for a real CPU.
- Probe identity first, batch up to the tool limit, and guard later calls with the expected module identity.
- Writes are non-transactional; report `partialMutation` and read changed addresses back.
- Use position numbers, identifiers, and real catalog objects for racks/modules. Never branch on localized display text or locale-formatted numbers.

## Boundaries and recovery

- [PublicAPI verified V16-V21] Openness does not expose live PLC values or force activation. Watch/force tables are engineering definitions, not a runtime value channel.
- [PublicAPI verified V16-V21] There is no Openness trace acquisition API, GSD/GSDML installation API, or CFC composition API. Install GSD files in TIA's GUI before using their device parameters.
- [recovery] Compile diagnostics, invalid parameters, missing dependencies, wrong targets, and failed readback are repaired from the returned state while successful work remains in place.
- [boundary] `*_NOT_SUPPORTED`, `*_NOT_EXPOSED`, and `*_UNSUPPORTED*` identify a structural route boundary and point to the supported alternative.
- [manual gate] Trust/UAC/modal cards resume the same operation after the user action.
- [timeout] Advanced instance registration exposes `power_on_timeout_ms`; other Openness calls use bridge-owned time bounds and return the next actionable state.
