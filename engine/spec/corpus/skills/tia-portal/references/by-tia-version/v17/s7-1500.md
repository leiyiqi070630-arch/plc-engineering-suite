# TIA Portal V17 - S7-1500

> Scope: facts for TIA Portal V17 with S7-1500. Evidence labels preserve the source strength; a fact verified on another release is not promoted to verified here. Source basis: repository generator/runtime contracts, the shared environment reference, and the real-machine evidence cited here.

## Version route

- [route-defined] SIMATIC SD is unavailable. LAD/FBD uses the deterministic `tia_lad_*` SimaticML generator.
- [verified route] Interface namespace v5 starts at V17; V17 omits the block `Namespace` element.
- [delivery] `tia_lad_generate_block_xml` validates the plan while generating. Import the coherent block set and use one final compile result.
- [hardware catalog] V17 Openness has no live TiaPortal.HardwareCatalog API. PLC Code's tia_openness_search_equipment_catalog therefore uses its bundled V17 CPU compatibility catalog for S7-1200/1500/300/400. Copy a returned CPU typeIdentifier verbatim into add_network_device; /V is the catalog module version, not CPU firmware. The fallback is CPU-only, so rack modules still require a source-backed order number plus the real rack path and free slot.
- [known defect] V17 technology-object parameter reads can be empty and writes may time out. Treat skipped parameters as a version limit; restarting Portal does not repair it.
- [verified route] GRAPH generation/import is supported with the built-in V17 stamp.
- [Openness] The V16-V20 public key is `d29ec89bac048f84`.

## Authoring and validation

- [delivery] Generate the requested block set directly and land related objects in one dependency-ordered batch. The generator validates its own plan; specification, evidence, and export tools are diagnostics for a concrete failed shape.
- [rule] For every non-Bool FB-call formal parameter, provide `datatype` explicitly. An omitted type can render as Bool and fail only at import/compile.
- [rule] Power-flow pins and data pins are different. TON.IN and counter CU/CD/R/LD consume power flow; PT/PV/value operands use data accesses. Do not wire an Access directly to a power-flow pin.
- [V18-grounded XML] ADD/MUL are variadic and require `Card`; SUB/DIV are binary; MOVE uses `out1`; comparators use `pre`; CALCULATE is the `Calc` part with an Equation.
- [instruction facts] Ones' complement is `INVERT`, not `INV`. SR is reset-dominant; RS is set-dominant. CTD output is `Q`; QU/QD belong to CTUD. SCL inputs use `:=`, outputs use `=>`.
- [block rule] FC cannot contain a stateful `VAR` section; use formal parameters and `VAR_TEMP`, or use an FB for retained state.
- [tag rule] Omit `table_name` to use TIA's localized default tag table. Never assume the English name `Default tag table`.
- [persistence] Mutation tools default to an unsaved in-memory change. Save once at meaningful milestones after device creation, completed block import, or successful compile.
- [retentivity] LAD XML generation does not emit member remanence and rejects a `retain` plan field. Use a supported SD `var_retain` route where available, SCL/DB `VAR RETAIN`, or configure retain on the real object; never silently ship a non-retentive result.
- [learning] Experiments stay unsaved, use temporary names, and must be deleted and confirmed. Requested project work is preserved at explicit milestones.

## CPU-family rules

- [language] S7-1500 IEC timer instances use `TON_TIME`, `TOF_TIME`, `TP_TIME`, or `TONR_TIME` and invoke their methods.
- [language] CASE supports CHAR/STRING. A FOR counter additionally supports LINT/ULINT.
- [standard OB] A non-optimized standard OB needs at least 20 bytes of local start information. On 1500, the alternative is the optimized-access pragma after the block header.
- [technology objects] PID_Compact is a TO, not merely an instruction. Create the TO body first, read the installed TO type/version, then generate the call. Axis formals use generic `TO_Axis`. Auto-tuning is online-only.
- [hardware] A rack CPU has no onboard process I/O. Unmapped %I/%Q can compile with a warning and then read as silent zero in simulation. Plug and verify real DI/DQ coverage before behavioral claims.
- [runtime] ISO-on-TCP normally uses rack/slot 0/1. Absolute DB access requires PUT/GET permission and a standard DB; optimized DB members need a symbolic channel.
- [Web API] On standard/T/F firmware the official Web API begins at V2.8 for core API/read methods, with later methods added through V3.1. R/H can log in from V3.1 but lacks most browse/program/diagnostic reads. Probe supported methods instead of assuming the table.
- [security] Fresh firmware >= V2.9 can have independent access-level and confidential-configuration defaults. Read both before configuration; do not weaken a real-controller project without explicit intent.

## Combination-specific notes

- [V17 TO limit] Empty/skipped TO parameter reads and write timeouts are a known version defect; use manual configuration or another verified TIA version when required.

## Simulation and behavioral proof

- [simulation] When simulation is requested, `tia_plcsim_plan` returns the compatible route and package set in one call; environment diagnostics are used when that route reports an environment problem.
- [behavior route] Requested behavioral simulation runs as one continuous compile -> download -> RUN -> stimulus -> observed readback sequence.
- [timed behavior] `tia_plcsim_assert_behavior` combines pulses, delays, latches, and timed assertions in one call when those checks are part of the request.
- [runtime ownership] The selected simulator tool family owns its runtime lifecycle. Trust/UAC/modal cards pause and resume that same operation.
- [network] Standard PLCSIM uses its Softbus route; PLCSIM Advanced exposes TCP/IP when started in TCP/IP network mode.
- [real-machine verified backend family] V17 uses PLC Code's net48 legacy WCF/x86 VPLC sidecar.
- [capability] Output image is readable. Address-based writes are input-only; symbolic writes can target downloaded I/Q/M/DB names. Confirm non-output writes through resulting Q behavior.
- [known environment finding] A legacy holder timeout may be caused by an admin compatibility flag; diagnose once rather than killing processes.

## Online values and configuration

- TIA Openness itself cannot read current values. Use the S7 runtime channel for supported absolute addresses and the official Web API for read-only symbolic/optimized data and diagnostics when configured.
- Probe identity/method support first. Batch operations, read mutations back, and report partial writes exactly.
- Web API prerequisites are: enabled web server, API enabled, an authorized web user, downloaded configuration, and explicit handling of a confirmed self-signed certificate.
- PLCSIM Advanced can verify the Web API only in TCP/IP adapter mode with web configuration downloaded; the local source marks this path manual-grounded but not yet end-to-end tool-proven.
- OPC UA/Webserver attributes must be read before write. Safety administration requires an F-CPU plus installed Safety/Openness options; Openness does not compose F-LAD internals.

## Boundaries and recovery

- [PublicAPI verified V16-V21] Openness does not expose live PLC values or force activation. Watch/force tables are engineering definitions, not a runtime value channel.
- [PublicAPI verified V16-V21] There is no Openness trace acquisition API, GSD/GSDML installation API, or CFC composition API. Install GSD files in TIA's GUI before using their device parameters.
- [recovery] Compile diagnostics, invalid parameters, missing dependencies, wrong targets, and failed readback are repaired from the returned state while successful work remains in place.
- [boundary] `*_NOT_SUPPORTED`, `*_NOT_EXPOSED`, and `*_UNSUPPORTED*` identify a structural route boundary and point to the supported alternative.
- [manual gate] Trust/UAC/modal cards resume the same operation after the user action.
- [timeout] Advanced instance registration exposes `power_on_timeout_ms`; other Openness calls use bridge-owned time bounds and return the next actionable state.
