# tia_plcsim_plan — extended contract

Reference data moved from the resident card on 2026-09-18. Current schema, diagnostic receipts, user scope and target version take precedence; historical measurements are scoped observations. Read only for an unresolved detail.

FIRST call when a simulation step is actually next (project and CPU exist, download is imminent): returns this machine's real simulation capability plus the complete ordered call sequence to reach the goal FOR THE ONE CPU you name. It is the SIMULATION PHASE entry point, not a task-starting survey: do NOT call it before the project and CPU exist, nor front-load it ahead of project creation, hardware, tags, and program generation. One call replaces the probe-and-get-refused loop — it decides the simulator backend, states what that backend can read/write, pre-fills every already-known argument, names the success criterion of EVERY step plus the timing and the recovery (onFailure) of the steps where those apply, and lists environment blockers with the exact user action for each (blockers always carry id/severity/what/evidence/action). MEASURED shape of the emitted steps (recorded R135 plans; 12 steps across 3 plans): successCriterion 12/12 and never empty, onFailure 8/12, timing 5/12 — always present on the executable `go` steps except the read-only route probe and the teardown, so read them rather than assuming every step carries all three. SCOPE (E2E R135): the sequence covers exactly one CPU, because this tool reads no project file and cannot enumerate a project's CPUs — a six-CPU plant project got verdict=go with unknowns=[] and a sequence bound to one CPU, and only that CPU was ever downloaded or simulated. For a multi-CPU project, call tia_openness_list_devices and run this planning step once per CPU; the returned `scope` object says the same thing, and `doNot` forbids reporting a plant-level verdict from one plan. Offline and cheap: it reads the Windows registry and files only, and never starts TIA Portal, PLCSIM or a bridge. Two situations must be told apart before calling: if the project does not exist yet, or exists without its CPU (hardware never created or not read back), do NOT call this tool — create the project and place/read the CPU first, then return here when a simulation step is actually next. If the project already has its CPU and only the route metadata (tia_version, family, project_type_identifier, device_name) is not yet in hand, calling with those fields omitted is allowed: the tool answers with the machine picture plus the exact calls producing the missing facts, then re-plan. Its route verdict comes from the same function tia_plcsim_standard_start and tia_plcsim_advanced_register_instance enforce, so verdict=go cannot be refused by the tools it points at, and verdict=blocked means those tools refuse it too (act on the blockers and alternatives instead). After a plan is returned, do NOT call tia_plcsim_standard_status to confirm it: that tool re-runs the identical assessment and cannot answer differently.
