Second account-level gate for a TIA connection problem: Siemens also requires the CURRENT Windows account to be a member of the local group "Siemens TIA Openness"; an account outside it cannot connect at all. Reads the bridge's group state only — no Openness attach, no registry write, no elevation. In the group ⇒ OK, this is not the blocker (look at the whitelist / Portal / component checks instead). Not in the group ⇒ ERROR TIA_OPENNESS_GROUP_MEMBERSHIP_MISSING, which raises the desktop's 「加入 Openness 组」 one-click; after the user confirms and passes the Windows administrator prompt the desktop adds the current account, this exact call is retried, and it reports the one step left (sign out of Windows and back in). Do not call it speculatively. Order for a connection problem: tia_openness_status → tia_openness_check_whitelist → tia_openness_request_bridge_trust (whitelist) → this tool (group) → retry the call you originally wanted. Tell the user the one sentence they need, never a lecture about Openness.
