# tia_lad_generate_block_xml — extended contract

Reference data moved from the resident card on 2026-09-18. Current schema, diagnostic receipts, user scope and target version take precedence; historical measurements are scoped observations. Read only for an unresolved detail.

Generate real SimaticML LAD (ladder) block XML directly from one complete structured plan. The generator validates the plan in the same call. It emits native V16/V17/V18 documents and V18-format documents accepted by V19/V20/V21. tia_version, schema_version, or plan.schema_version selects the document version. target_family and block_number are accepted either inside plan or at tool-call level, so classic S7-300/400 blocks receive their non-optimized envelope. Supports contacts/coils/branches, FB/FC calls, MOVE, TON/TOF/TP/TONR, compare/math/convert/scale/shift/counters/edges, communication, motion, and PID instruction boxes. For import, readback or file delivery, set output_path/output_directory in the first call to write the XML. Omitted returns XML only and creates no file; do not glob for an unwritten artifact. callee_interfaces can come from blocks generated in the same task or an existing callee export. Review returned logicSummary against requirements. When the task includes IDE changes, batch related imports, compile and save. Compile proves project consistency, not behavior. Look up a missing required instruction/pin shape before generating; reuse known contracts. Real-machine V21 plan-shape rules: a timer network's static instance member must be declared TON_TIME (IEC_TIMER is rejected by plan validation); a fb_call to a GLOBAL instance DB must pass instance:{name:"DB_x", scope:"GlobalVariable"} (LocalVariable renders the multi-instance form and TIA then reports 'Missing instance DB' at compile); contact_coil power is OR(branch legs) AND all contacts. Three alternative paths need three branch objects, not two branches plus contacts.
