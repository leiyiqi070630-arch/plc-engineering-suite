# tia_openness_request_bridge_trust — extended contract

Reference data moved from the resident card on 2026-09-18. Current schema, diagnostic receipts, user scope and target version take precedence; historical measurements are scoped observations. Read only for an unresolved detail.

Ask the user to trust the PLC Code TIA bridge binary, with the desktop's one-click flow. Runs exactly the same read-only whitelist probe as tia_openness_check_whitelist and then answers in one of two ways. (1) Already trusted: returns OK with the binary's SHA256 and the list of TIA versions that trust it — nothing to do; if TIA still cannot connect, the other account-level gate is the Windows group (tia_openness_request_group_join). (2) Not trusted: returns an ERROR carrying TIA_BRIDGE_WHITELIST_HASH_STALE (rebuilt after the last registration) or TIA_BRIDGE_WHITELIST_ENTRY_MISSING (never registered for this exe path), which is what makes the desktop raise its 「一键信任桥接」 confirmation; after the user confirms and grants the Windows administrator prompt, this exact call is retried and then reports OK. Call it when you have just rebuilt the bridge, or when a read-only check showed a stale/missing entry, and you want the fix offered in-app instead of telling the user to go find the button. Permission is ReadOnly because THIS TOOL only hashes a file and reads the registry — it writes nothing, requests no elevation, and cannot register anything by itself; the registration is performed by the desktop only after the user passes BOTH the in-app confirmation and the Windows UAC prompt. Do not call it speculatively before a whitelist problem is known: on an already-trusted machine it is a no-op, and on an untrusted one it interrupts the user.
