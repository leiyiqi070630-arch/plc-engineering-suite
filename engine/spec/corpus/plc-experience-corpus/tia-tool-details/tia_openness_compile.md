# tia_openness_compile — extended contract

Reference data moved from the resident card on 2026-09-18. Current schema, diagnostic receipts, user scope and target version take precedence; historical measurements are scoped observations. Read only for an unresolved detail.

Compile one exact PLC software target or a specific block/type in the active TIA Portal project and return structured diagnostics. Mutating (writes compile state). ErrorCount > 0 or compiler state Error returns TIA_COMPILE_ERRORS; a missing/non-numeric ErrorCount or unknown state returns TIA_COMPILE_RESULT_UNVERIFIABLE instead of failing open. Success, Information, and Warning with zero errors remain successful. Use scope=project to aggregate all device hardware/software compiles, or scope=plc-project for PLC devices only. These scopes cannot be combined with an individual target. Default scope=target still requires an exact device in multi-PLC projects. Project results include per-target diagnostics and unknown totals remain null. Use after a mutation when the prior write/import/create tool did not already compile the changed object; avoid redundant repeat compiles of unchanged objects. For HMI compilation, pass target_path from hmi_tree (for example Device/HMI). Classic HmiTarget uses its compile provider. WinCC Unified HmiSoftware is compiled through its owning Device, covering device hardware and HMI software; requestedTargetPath and compiledBlocksScope disclose the actual scope. Compiler errors must be resolved before claiming a clean HMI compile. ONE exception is not a code problem: for Classic Basic/Comfort panels the error 'Runtime settings: No start screen defined or the start screen has been deleted.' is a device-level runtime setting with NO Openness write path in V15.1-V21 (verified live and in every installed API document) - do not hunt attribute names, alternate tools or XML imports. Either tell the user this needs their one click in TIA (HMI device > Runtime settings > General > Start screen), or use a panel that already has it configured through tia_openness_create_from_master_copy (see tia_openness_set_hmi_start_screen). A SECOND default-of-the-device case, measured on a freshly added V21 Unified Comfort panel (MTP700) on 2026-09-16: it compiles with exactly two Runtime settings errors - 'The entered password confirmation does not match the password.' and 'The entered password does not comply with the password security concept: At least one special character, at least one number, minimum length of 8 characters, one lower case and one upper case letter.' - before any PLC Code write touches it, and the V21 Unified API exposes no writable password member (reflecting Siemens.Engineering.WinCCUnified.dll of Portal V21: only EnableUsernameAndPasswordAuthentication is writable), so that is the same class of device-level setting: fix it once in TIA and recompile, or start from a configured panel. Objects written through the HMI tools do NOT contribute errors when used correctly - the same panel compiled 3 errors while it held a mapping row whose 1..5 range did not fit its BOOL tag, and went back to the 2 default ones after that row was addressed (measured live). A THIRD error text names the environment, not the code: 'The device is not supported and cannot be compiled. Please change to a supported device.' means the panel's DEVICE VERSION is not in this TIA release's catalog - measured 2026-09-18 on V20: a TP700 Comfort migrated from a V18 project keeps device version 16.0.0.0, while the V20 catalog for that panel contains only 14.0.1.0 and 17.0.0.0, so it can never compile; read_hardware_identifier returns an EMPTY typeIdentifier for such a device, where a natively created panel returns its OrderNumber. Do not reinstall TIA/PLCSIM and do not re-open the project: change the device version in the device properties, or add/re-create the panel at a version the installed catalog lists.
