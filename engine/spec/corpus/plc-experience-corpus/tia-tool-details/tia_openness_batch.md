# tia_openness_batch — extended contract

Reference data moved from the resident card on 2026-09-18. Current schema, diagnostic receipts, user scope and target version take precedence; historical measurements are scoped observations. Read only for an unresolved detail.

Run a sequence of TIA Openness operations under ONE attach to the running TIA Portal instead of one attach per call; the preferred way to land a MULTI-BLOCK program. Order ops by dependency (UDTs -> tag tables -> called FB/FC -> instance/global DBs -> callers/OBs); with several imports, compile-after-import defers automatically on earlier ones; only the final import (or a trailing compile) yields the whole-PLC verdict. Chains batch the same way: add-network-device xN -> create-subnet -> connect-device-to-subnet; cleanup: delete-object xN (`object-path`, optional `kind`=block/tag_table) -> delete-tag-table (`table-name`/`table-path`); then save -> compile. Delete FB + its instance DB together — TIA may auto-restore the DB on the next compile (R005). create-instance-db may compile internally when a fresh FB is inconsistent — prerequisite, not the final verdict. Each `operations` entry is {command, options}: bridge command name + kebab-case/hyphen keys (e.g. `device-name`). `save-project` normalizes to `save`; write-source may carry inline `source-text`; create-tags accepts nested data_type/data-type/dataType and logical_address/logical-address/logicalAddress aliases. Nested batch rejected; confirm=true is inherited by sub-operations unless overridden. Set tia_version/project_match ONCE at batch level — not in `defaults`, not per sub-op (engine hoists a uniform project-match; differing projects rejected). Optional `defaults` takes routing keys only: device-name, hmi-device-name, target-group-path, destination-group-path, folder-path. continue_on_error=true keeps going past a failed op (default stops). Requires confirm=true. A batched write-source/create-instance-db needs explicit `device-name`. For create-instance-db a SINGLE call may omit it (the only PLC is then used; several PLCs fail closed with TIA_TARGET_PLC_AMBIGUOUS), while `write-source` needs an explicit `device-name` on every call, batch and single alike — a batch without it fails BRIDGE_REQUIRED_OPTION_MISSING. On failure read operations[] — the envelope reports only TIA_BATCH_PARTIAL + the count that ran.
