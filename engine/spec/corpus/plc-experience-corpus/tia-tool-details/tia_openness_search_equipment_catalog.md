# tia_openness_search_equipment_catalog — extended contract

Reference data moved from the resident card on 2026-09-18. Current schema, diagnostic receipts, user scope and target version take precedence; historical measurements are scoped observations. Read only for an unresolved detail.

Resolve an exact hardware typeIdentifier. V18+ searches the live installed TIA HardwareCatalog. V16/V17 have no HardwareCatalog API, so this same tool automatically uses PLC Code's bundled, version-scoped CPU compatibility catalog for S7-1200/1500/300/400; those fallback results are CPUs only and label machine-verified creation separately from catalog-listed compatibility. REQUIRES a running TIA Portal of tia_version (the bridge attaches to it): if none is open the call fails with TIA_NO_RUNNING_PORTAL — call tia_openness_ensure_portal first, then retry this same call. QUERY: use a bare order number ('6ES7 511-1AK02-0AB0') or family/model term ('CPU 1511'); the V16/V17 fallback also tolerates OrderNumber: and /V suffixes. The CPU creation suffix is the TIA catalog module version, not a claim about CPU firmware. For rack modules, read the real rack path/free slot and use a source-backed module order number; the V16/V17 CPU fallback is not a signal-module catalog. On V18+, a 3rd-party/distributed device appears only after its GSD/GSDML is installed manually in TIA. On V16/V17 a signal-module or model-term query ('CPU 1511-1 PN', '1511') returns empty results plus a catalogMiss hint BY DESIGN — use a full order number ('6ES7 511-1AK02-0AB0'); one attempt is the budget, then plug_rack_module with the exact order number or report the hardware limitation.
