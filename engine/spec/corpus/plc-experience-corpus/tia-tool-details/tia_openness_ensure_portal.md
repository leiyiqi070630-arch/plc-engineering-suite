# tia_openness_ensure_portal — extended contract

Reference data moved from the resident card on 2026-09-18. Current schema, diagnostic receipts, user scope and target version take precedence; historical measurements are scoped observations. Read only for an unresolved detail.

Ensure a Siemens TIA Portal process is running and Openness-attached, WITHOUT opening, creating, or touching any project. Attach-or-start: a compatible Portal already running reports action=already-running; one still booting is adopted; finding none starts a fresh Portal with a visible GUI (a cold start can take minutes). Mutating; requires confirm=true. tia_version V16-V21 (bare "20" accepted); omitted resolves like every other TIA tool. This tool NEVER starts a second Portal of a DIFFERENT version while another is running: such a call fails TIA_NO_RUNNING_PORTAL naming the running versions — do NOT retry; instead omit tia_version to bind the running Portal, or open/create the project with open_new_portal_if_needed=true. If the OS sees a same-version Portal process but attach fails, the call returns TIA_PORTAL_VISIBLE_BUT_UNATTACHABLE instead of spawning a duplicate GUI — the error names the next step (typically a modal/trust dialog in the visible Portal; on V16 instance discovery is unreliable, opening the GUI manually is safer). Creating, opening, or retrieving a project already starts a Portal, so use THIS tool only when a Portal must be present before any project action.
