## 3. 三类高价值内容

### 3.1 工具契约（`contracts.json` → `tool_contracts/`）

```json
{
  "authority": "compiled mvp_tool_specs (source schema)",
  "contracts": [
    {
      "contract": {
        "name": "mitsubishi_csv_generate",
        "description": "Generate a Mitsubishi GX Works2 list-format PROGRAM CSV (FX2/FX3) from structured rungs. …",
        "permission": "ReadOnly",
        "inputSchema": { "properties": { "family": …, "project_name": …, "rungs": { … } }, "required": ["family","rungs"] }
      },
      "contractHash": "78db979e0bf90288fa05b208fbd073801b900f2a2bcd47e8fdb7f2d091847b52"
    }
  ]
}
```

- 32 份契约，权限分布：`DangerFullAccess` 15 / `WorkspaceWrite` 13 / `ReadOnly` 4。
- `contractHash` 是契约指纹 —— 说明引擎会在运行时校验"契约是否变更"，可作为升级断点。
- 已拆成单文件：`spec/tool_contracts/tools/<name>.json`，汇总表 `TOOLS.md`。

### 3.2 实测证据（`evidence/`）

例如 `evidence/tia-watch-symbolic.offline-generation.json`（5.04 MB）：一次 watch 表符号化生成的完整
离线证据链。同类文件构成"什么被真机验证过"的账本 —— 引擎在提示词里反复强调
「compile 不等于运行」「import 成功不等于 LAD body 存在」，这些证据就是那句话的来源。

### 3.3 代码产物（`artifacts/`）

抽一个 `tia-sd-box.s7dcl`：

```text
{
    S7_Optimized := "TRUE";
    S7_Language := "LAD";
}
FUNCTION_BLOCK "FB_SD_box"
    VAR_INPUT
        Value : Int;
    END_VAR
    VAR_OUTPUT
        Limited : Int;
    END_VAR
    { S7_Language := "LAD" }
    NETWORK
        RUNG wire#powerrail
            LIMIT( MN := 0, IN := #Value, MX := 100, OUT => #Limited )
```

这是能直接导入 TIA Portal V20+ 的 SIMATIC SD 文本，**可作为自己生成器的金标准样本**。

## 4. 工具卡片长文本（`long_texts_tool_cards.txt`）

459 条 > 1500 字符的字符串，是给模型看的**工具卡正文**，最长的 55 KB。内容特点是：

- 精确到错误码的失败语义（`object_delete_blocked_by_online_session` → `data.requiredAction`）；
- 实测环境标注（"实测 V20 + CPU 1513-1 PN"、"E2E V2 R053 measured 347 ms against nominal 2000 ms"）；
- 明确的"不要做什么"（"never emulate a timer with self-holding contacts"、"do not insert a manual compile
  before generating"）；
- 中英混排，中文部分多是现场修复指引（`修复(target_path): …`）。

这批文本是引擎真正的"专业能力"载体 —— 比代码更能解释它为什么能写出能编译的 LAD。

## 5. 语料的组织约定

新增或修改语料时遵循这几条，保证引擎能直接消费：

1. **目录即分类**：`cases/` 放输入，`evidence/` 放对应输出与实测记录，文件名同源（`<tool>-<case>.json`）。
2. **产物可直接使用**：`artifacts/` 下的 `.s7dcl`、HMI XML、PLCopen TC6 必须能被对应 IDE 直接导入，
   不做二次包装。
3. **证据带环境标注**：每条实测记录注明版本、CPU、日期（例如「实测 V20 + CPU 1513-1 PN」），
   避免把单机结论当通用规则。
4. **失败也入库**：被拒绝的形状（`plcopen_project_box_coil_unsupported` 等）要留样例，
   这是边界知识的来源。
5. **非 UTF-8 资源**：原始字节放在 `_non_utf8/`，文件名保留原路径（`/` → `__`）。
